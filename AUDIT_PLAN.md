## Критично

### [x] C1. Реестр сетей: КАМ может завести сеть на чужое имя, переназначить или обнулить владельца

Три отдельные грани одной проблемы:

1. `CreateNetwork` берёт `input.KAM` из тела запроса и пишет в базу, не сверяя с закреплением
   вызывающего. Роль `kam` к маршруту допущена → любой КАМ создаёт сеть в чужом портфеле.
2. `UpdateNetwork` — то же самое. `NetworkAccessRequired` проверяет только *текущего* владельца,
   поэтому чужую сеть не открыть, но свою можно переписать на кого угодно и потерять безвозвратно.
3. У `name` и `network_type` есть откат на `current.*`, если клиент их не прислал, а у `kam` — нет.
   PATCH без поля `kam` → пустая строка → `nullIfEmpty("")` → `kam = NULL`. Сеть остаётся без
   владельца и пропадает из реестра у всех КАМов сразу.

**Что сделать:** откат на `current.KAM` при отсутствии поля в PATCH; для роли `kam` — проверка
`input.KAM == ownKAM` и в `CreateNetwork`, и в `UpdateNetwork`.

```
backend/handlers/network.go:409    CreateNetwork — kam из тела запроса
backend/handlers/network.go:511    UpdateNetwork — нет отката на current.KAM
backend/repository/network_repo.go:152   nullIfEmpty(kam)
```

**Образец:** `backend/handlers/promo.go:599` и `:614` — `SavePromo` берёт КАМа из базы и проверяет
область дважды: до применения входящих данных и после, чтобы закрыть перенос записи за пределы
своей области.

### [x] C2. Пустая область видимости трактуется как «ограничений нет»

`KAMAllowedByScope` возвращает `true`, если список области пуст. Решение осознанное и описано
в README («учётная запись без закрепления и без области не ограничивается»), но следствие:
учётка с ролью `kam`, заведённая через `bootstrap_user` без `tbl_Users.kam` и без строк
в `tbl_ApprovalScope`, получает доступ ко всем промо компании — и на чтение, и на запись.
Один пропущенный шаг при заведении пользователя открывает весь портфель.

**Что сделать:** сохранить текущее поведение для `admin` и унаследованных ролей согласования,
но для роли `kam` отсутствие закрепления считать пустой областью — с явным сообщением в интерфейсе
«учётная запись не привязана к КАМу», а не молчаливой пустой таблицей. Failure-режим должен быть
fail-closed.

### [x] H1. Фронтенд не отдаёт ни одного заголовка безопасности

Проверено вживую на демо-контуре: в ответе nginx нет `Content-Security-Policy`,
`X-Content-Type-Options`, `X-Frame-Options`/`frame-ancestors`, `Referrer-Policy`.
Заодно раскрывается версия (`Server: nginx/1.29.8`).

Критично именно здесь: access-токен хранится в `localStorage` (`frontend/src/api/promo.ts:59`),
поэтому любая XSS означает угон сессии. CSP — основная защита от этого сценария.

**Что сделать:** в `frontend/nginx.conf` добавить `default-src 'self'` с явным разрешением для
Google Fonts, `frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`,
`Referrer-Policy: strict-origin-when-cross-origin`, `server_tokens off`.

### [x] H3. `BuildBaseWhere` молча проглатывает ошибки разбора чисел

Три условия вида `if y, _ := strconv.Atoi(...); true` всегда истинны — ошибка отбрасывается,
условие применяется с нулём:

- `yearFrom=abc` → `year >= 0` (фильтр как будто применён, но не фильтрует);
- `months=abc` → `month IN (0)` → пустая выдача без объяснения причины.

Один и тот же ввод даёт разный результат на двух витринах одного портала.

## Что менять не нужно

Чтобы при правках случайно не сломать то, что сделано правильно:

- **Контракт API описан один раз** — в Go-структурах; `frontend/src/types/api.generated.ts`
  генерируется через `make types`, а `make types-check` в CI падает при расхождении.
- **JWT без слабого fallback:** секрет короче 32 символов роняет приложение до старта HTTP-сервера;
  валидация пиннит `HS256`, issuer, audience, требует `exp` и проверяет тип токена.
- **Одноразовые refresh-токены:** хранится только SHA-256; повторное предъявление гасит *все*
  сессии пользователя и пишет `refresh_token_reuse_detected`.
- **`config.ValidateRuntime()`** отсекает опасные значения по умолчанию в production ещё до
  первого запроса.
- **Тай-брейк по `n.id` в `ORDER BY`** — без него `OFFSET/FETCH` терял бы строки между страницами.
- **Область видимости входит в ключ кэша справочников** — без этого срез одного КАМа достался бы
  другому.
- **`userScopedKey` вынесен внутрь `DataTable` и хука фильтров**, чтобы про скоупинг нельзя было
  забыть в новой странице.
- **Выгрузка в Excel через `StreamWriter` прямо из курсора БД** — не накапливает строки в памяти.
- **Дашборд промо пересчитывает ROI на сопоставимом срезе**, а не усредняет готовые проценты строк.
- **SQL-инъекций не найдено**, `dangerouslySetInnerHTML` в кодовой базе нет, CORS проверен вживую
  (preflight с чужого origin → 403), секретов в Git нет.
