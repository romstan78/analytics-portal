**Дата:** 20.08.2026
**Ветка:** `codex/approval-inbox-ui` (коммит `edb572a`)

## 1. Что это

Аналитический портал для интернет-продаж и согласования промо-акций.

| Слой | Технологии |
|---|---|
| Backend | Go 1.25.7, Gin, MSSQL (`microsoft/go-mssqldb`), squirrel, goose, excelize |
| Frontend | React 19.2, TypeScript, Vite 8, MUI v9, Recharts, React Query |
| Данные | Python 3 + pyodbc/pandas: синхронизация OLAP, импорт промо, дедупликация |
| Инфраструктура | Docker Compose, nginx, SQL Server 2022 |

Объём: ~16 000 строк кода, 119 файлов под Git. Проект прошёл серию аудитов (этапы 0–6), и значительная часть замечаний реально закрыта.

---

## 2. Сильные стороны

- **Аутентификация сделана честно.** Нет fallback-значения JWT-секрета — приложение падает на старте, если секрет короче 32 символов (`backend/config/auth.go:27`). Access- и refresh-токены разделены по типу, при валидации проверяются issuer, audience, алгоритм подписи и обязательный `exp`. Refresh-токен хранится в httpOnly cookie со scope `/api/auth`.
- **`ValidateRuntime()`** (`backend/config/auth.go:53`) запрещает в production `DB_AUTO_CREATE`, пустой `CORS_ORIGINS`, `*`, localhost, loopback-адреса и не-HTTPS origins. Такую проверку закладывают редко.
- **Целостность согласований.** Optimistic locking по `updated_at`; массовое согласование выполняется одной транзакцией с `UPDLOCK, ROWLOCK` и сортировкой по ID для снижения риска deadlock (`backend/repository/promo_repo.go:1115`). Конфликт версии → `409`, весь пакет откатывается.
- **SQL безопасен.** Все значения параметризованы; динамические имена колонок берутся исключительно из хардкод-констант — пользовательский ввод в имена колонок не попадает ни в одном из проверенных мест.
- **Экспорт промо в Excel** реализован потоково (`sql.Rows` + `NewStreamWriter`), без загрузки всей выборки в память.
- Goose-миграции встроены в бинарник; скрипт дедупликации ведёт журнал и поддерживает полный откат по `run_id`; реализованы graceful shutdown, soft-delete + restore, audit log.
- **Проверки проходят:** `go vet ./...` чисто, backend unit-тесты и 18 Python-тестов зелёные. Интеграционные тесты отказываются запускаться на БД без суффикса `_test` — хорошая защита от затирания рабочих данных.

## 3. Находки

### 3.1. Фронтенд-проверки не проверяют ничего — **критично**

- Пакет `typescript` не установлен вообще: его нет ни в `package.json`, ни в `node_modules`. `npx tsc --noEmit` не запускается.
- `npm run build` — это `vite build`, а esbuild типы не проверяет. Следовательно, `strict: true` в `frontend/tsconfig.json` не применяется **никогда**.
- ESLint настроен на `files: ['**/*.{js,jsx}']` (`frontend/eslint.config.js:12`), тогда как весь код — `.ts/.tsx`. Фактически линтуются два файла: сам `eslint.config.js` и `vite.config.js`. Ноль из ~30 файлов в `src/`.

**Следствие:** `make test` для фронтенда сейчас сводится к линту двух конфигов, двум unit-файлам на утилиты и сборке без типов. Долг уже виден в коде: `frontend/src/App.tsx:119` — `function PlaceholderPage({ title, description })`, а также `handleLogin = (data)`; при включённом strict это ошибки implicit `any`.

### 3.2. `/api/data?all=true` загружает всю таблицу в память — **высокий приоритет**

`backend/handlers/sales.go:413`. Без лимита и без стриминга: любой авторизованный пользователь одним запросом может исчерпать память процесса. В том же цикле `if err := rows.Scan(...); err != nil { continue }` — строки теряются молча, `rows.Err()` не проверяется. Контраст с промо-экспортом, где всё сделано правильно, особенно заметен.

### 3.3. Git-репозиторий раздут до 143 МБ — **высокий приоритет**

В истории семь версий Go-бинарников по ~31 МБ, и файл `backend/backend` **до сих пор отслеживается**: `.gitignore` его перечисляет, но правило игнорирования не действует на файлы, уже попавшие в индекс. Также в истории лежит `upload/сборка` (9 МБ). Страдают время клонирования и будущий CI.

### 3.4. Access-токен в localStorage — **средний приоритет**

`frontend/src/api/auth.ts:7`. Перенос refresh-токена в httpOnly cookie — шаг правильный, но сделан наполовину: при XSS access-токен (15 минут жизни) всё равно утекает. Роль в localStorage проблемой не является — backend берёт роль из JWT, а значение в хранилище используется только для UI.

### 3.5. CI не существует — **средний приоритет**

Каталога `.github/` нет; есть только шаблон `ops/github-actions-ci.yml.example`. Все проверки выполняются вручную через `make test`. В сочетании с п. 3.1 регрессии типов и линта ловить нечем.

### 3.6. `TrustServerCertificate=1` захардкожен

`backend/config/db.go:33`, без возможности переопределить через окружение. Внутри Docker-сети это приемлемо, но при вынесении SQL Server за пределы хоста получается канал, уязвимый к MITM, и production-валидация конфигурации этот случай не отслеживает.

### 3.7. Logout не отзывает refresh-токен

`backend/handlers/auth.go:136`. Ограничение задокументировано честно как отложенное, но по факту украденный refresh-токен остаётся действительным 7 дней после «выхода».

### 3.8. Параметр `page` не защищён от отрицательных значений

`backend/handlers/promo.go:142`, `backend/handlers/promo.go:704`, `backend/handlers/sales.go:448`. `pageSize` клампится (1–500), `page` — нет: `?page=-5` даёт отрицательный `OFFSET` и ответ 500. Лечится одной строкой.

### 3.9. Rate limiter — per-instance, in-memory

`backend/main.go:37`. При двух репликах эффективный лимит удваивается. Кроме того, тяжёлые эндпойнты (экспорт, dashboard) имеют тот же лимит 100 запросов в минуту, что и лёгкий `/api/promo/filters`.

### 3.10. Документация разошлась с кодом

`project.md` в шапке заявляет «Go 1.22, React 18, MUI v5/v6» и `migrations/ (SQL-файлы + ensureTables())`. Фактически — Go 1.25.7, React 19.2, MUI v9, а `ensureTables()` удалён ещё в рамках задачи #3. Ниже по тексту файл сам это фиксирует, но шапка не обновлена.

## 4. Приоритеты

1. **Установить `typescript`**, исправить `files` в ESLint на `**/*.{ts,tsx}`, добавить `tsc --noEmit` в `npm run build` и в `make test`. После этого ожидается партия ошибок — это накопленный долг, а не новая поломка.
2. **Ограничить `all=true`**: либо стриминг по образцу промо-экспорта, либо жёсткий потолок строк с явной ошибкой при превышении. Заодно перестать глотать ошибки `Scan`.
3. **`git rm --cached backend/backend`** и коммит. Сжатие истории потребует переписывания и форс-пуша — отдельное решение, требующее согласования с командой.
4. **Скопировать шаблон CI** в `.github/workflows/` — без него пункты 1–2 со временем деградируют обратно.

Пункты 3.4, 3.6 и 3.7 — архитектурные компромиссы с понятной ценой. Их стоит зафиксировать как осознанное решение, а не чинить рефлекторно.
